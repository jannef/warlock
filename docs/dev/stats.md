# Stats

Developer notes for working on this part of Warlock (moved from CLAUDE.md, #185); the
rules it implements are in spec/08f-stats-and-burden.md. Keep it current with the code, as CLAUDE.md says.

Stats (spec §8 "Stats"; M14) live in `warlock-core/src/stats.rs`: `Stat` (Strength, Dexterity,
Toughness, Intelligence, Willpower, Presence; id, abbreviation, name) is generated by the
`stats!` list there, so **a new stat is one entry in that list** (saves change);
`PerStat<T>` holds one value per stat (serialized as a map by stat id), `Stats` an actor's scores
and potentials (`Actor::stats`, saved and hashed), and `modifier(score)` /
`Stats::modifier(stat)` the D&D 3.5 modifier (`floor((score − 10) / 2)`) for the rules. Content:
`stats` and `potential` tables (by stat id; 1 to 40; missing score 10, missing potential = the
score, never below it; `Stats::from_data` validates) on creature types in `data/creatures.toml`;
the player's come from their character (`docs/dev/character-creation.md`), or from a scenario without one
(`ScenarioDef::player_stats`; the `player` creature may not set any). **Never show a modifier, a potential, or a creature's stats**: presentation reads only
`PerceptionView::own_scores` (the player's scores as the rules read them, raised by magic items
and lowered by status effects, hunger, and stat damage; `own_base_scores` without those
penalties, so the character screen can mark the lowered ones) — the character screen and the `stats` dump layer; only the dev
`actors` layer and `--state` dumps show the rest. Only combat (Strength, Dexterity, Toughness),
burden (Strength and Toughness scores), digging and kicking doors in (Strength), and disease
checks use stats, **always through
`Actor::effective_stats(content)`** (worn magic raising them, then status penalties, Weak, and
stat damage; never `actor.stats` directly in a rule; the hit points a level adds,
`World::level_hp`, read `Actor::raised_stats`, before the penalties, so a passing penalty never
costs them for good), and
no other D&D concept (checks, saves) comes with them. The status bar has no stats segment: it is already
full at common window sizes (it shows `HP 17/17` right after the level name, dropping only
before it, and the burden right after that when there is one).

## Training (#231)

Stats grow by use, checked at levels (spec §8 "Stats": "Training"; design §6):

| Where | What |
|---|---|
| `content/stat_training.rs` | `StatTraining` from `data/stats.toml` (`[training]` `need_base`, `need_per_point`, `over_potential_divisor`, `[[training.use]]` `stat`/`on`/`chance`; validated, a stat and use listed once; without the file nothing trains), `StatUse` (the uses, `describe()` for the wiki, `of_skill` for the five uses skills share), `odds(marks, score, potential)` as a fraction. |
| `world/stat_training.rs` | `train_stat(StatUse)` (one training-stream draw per rule below 100; the player only, alive), `train_fight` (blow, shot, hungry_fight, hurt, big_hit: one call in `fight.rs::resolve`), `train_resisting` (disease checks won: Willpower's → `resisted_will`, else `resisted`), `check_stats` (from `World::level_up`, once per level gained: six `levels`-stream draws, always; a rise via `Stats::train`, which passes the potential and lifts it; marks to 0; Toughness's hit point at once; the message into `news`). |
| `world/train.rs` | `trains`/`train` also ask stats for the shared uses (`StatUse::of_skill`): one report at the hook trains both. |
| The hooks | one line each: `dig_turn` (dig), `after_tread` (plunge, climb onto ice), the pit in `spring_trap` (climb), `expose`/`disease_turn` (resisted), `search_turn` after a find (found), `read.rs` `use_up` (read) and `read_identify` (identified), `earn_kill` before the XP (discovered), `keep_at` ending `Done` after more than one turn (endured), `talk.rs` `chat` (chat; `ask` takes no time, so it trains nothing) and `swap_places` (swapped), `shop.rs` `pay` and a sale (trade), `quest.rs` `complete` before the XP (quest), `World::spend_mana` for the player, a cost above 0 (cast). |

`Actor::stat_marks` (`PerStat<u16>`, saturating) is saved and hashed, left out while all zero.
Nothing shows the marks but the dev `progress` dump layer (`stat marks St 3, To 1`); the wiki
tables are `xtask/src/wiki/stats.rs` (`stat-training.md` with the chances, `stat-checks.md`).
Tests: `world/stat_training_tests.rs`, `content/stat_training.rs`.
